# 판정 엔진 검증 도구

앱(`chart-sentinel-standalone.html`)의 판정·매매 규칙이 **과거에 실제로 돈이 됐는지**를 검증하는 도구입니다.
엔진 코드는 복사하지 않고 매번 앱 원본에서 그대로 추출하므로, 앱을 고치면 검증도 자동으로 새 코드를 씁니다.

## 빠른 시작

```bash
cd tools
npm run research:data        # 1) 54종 일봉 받기 (약 2분, data/ 에 저장 · git 제외)
npm run research:precompute  # 2) 코인·날짜별 판정 미리 계산 (약 10분)
npm run research:check       # 3) 엔진 단위 테스트 + 앱 화면 "과거 성과" 표 재현 검사
npm run research:portfolio   # 4) 포트폴리오 시뮬레이션 (학습·검증 구간, 전략 비교)
npm run research:empirical   # 5) 앱 화면 "과거 실측" 표 재계산·대조
```

단일 코인: `cd tools/research && node portfolio.js --coin BTC`
학습 구간만: `node portfolio.js --period train` · 비용 변경: `--cost 0.001` (편도)

## 파일

| 파일 | 하는 일 |
|---|---|
| `fetch-data.js` | Binance 공개 미러에서 일봉 수집. 상장폐지 코인 포함, 5일 넘는 공백(폐지 후 심볼 재사용)은 잘라 폭락이 그대로 반영됨 |
| `precompute.js` | 각 날짜에서 그날까지의 365봉만으로 판정 계산 (미래 정보 없음) → `data/feat_engine.json` |
| `portfolio.js` | 종가 신호 → 다음 날 시가 체결, 10슬롯, 장중 손절(갭은 시가), 편도 0.15%, 거래대금 필터 |
| `check-engine.js` | 엔진·채점 단위 테스트, 랜덤워크 편향 검사, 앱 화면 수치(`RULE_TRACK_RECORD`) 재현 (`--full`이면 포트폴리오 행까지) |
| `empirical.js` | 앱 화면 `EMPIRICAL_CRYPTO_1D` 재계산·대조 |
| `lib/engine.js` | 앱 원본에서 엔진 추출 (`.cache/engine.generated.js`, git 제외) |

## 지금까지의 결론 (2026-10 기준)

| | 2020~2022 연수익 / 최대 낙폭 | 2023~2026 연수익 / 최대 낙폭 |
|---|---|---|
| BTC에 앱 규칙 적용 | +57% / −34% | +19% / −40% |
| BTC 그냥 보유 | +32% / −77% | +53% / −53% |
| 코인 54종에 적용 (10슬롯) | +70% / −53% | −1% / −76% |
| 코인 동일비중 보유 | +56% / −85% | +8% / −76% |

- 앱 규칙(판정 롱 → 다음 날 시가 진입, 3 ATR 추적 손절, 익절 없음)은 **하락장 낙폭을 크게 줄였지만**, 2023~2026에는 BTC 보유보다 수익이 낮았습니다.
- 옛 규칙(눌림 지정가 + 고정 익절)은 모든 시험에서 가장 나빴습니다(알트 포트폴리오 2023~2026 연 −20%).
- 2023~2026에 알트 50개 중 47개가 BTC보다 부진했습니다.
- 파생 지표(펀딩비·미결제약정·롱숏·테이커)는 앱에서 계산 가능한 형태로는 예측력이 확인되지 않아 점수에 넣지 않았습니다.

## 검증 규칙 (꼭 지켜 주세요)

1. **규칙은 학습 구간(2020~2022)만 보고 고릅니다.** 검증 구간(2023-01-01~2026-10-20)은 고른 뒤 한 번만 확인합니다.
2. **검증 구간 결과를 보고 규칙을 다시 고치면 과적합입니다.** 이 구간은 이미 사용했으므로, 새 규칙의 깨끗한 검증은
   **2026-10-21 이후 데이터**나 앱 **성과 탭의 실제 기록**으로만 가능합니다.
3. 생존 코인만 쓰지 마세요. 이 도구의 유니버스에는 상장폐지·폭락 코인이 포함돼 있습니다(생존 10종만 쓰면 결과가 부풀려졌습니다).
4. 비용을 넣으세요. R(손절폭 단위)로 보면 짧은 봉일수록 수수료가 커집니다(BTC 5분봉: 왕복 0.2% ≈ 1.3R).
5. 5일 간격 같은 성긴 표본은 시작일만 바꿔도 결과가 크게 흔들립니다. 매일 표본이나 계좌 시뮬레이션으로 보세요.

## 엔진을 바꿨다면

1. `npm run research:precompute` → `npm run research:check -- --full`
2. 수치가 달라지면 앱의 `RULE_TRACK_RECORD`(과거 성과 카드)와 `EMPIRICAL_CRYPTO_1D`(과거 실측)를 새 결과로 갱신하고,
   `npm run research:empirical`로 대조한 뒤 다시 빌드(`npm run build`)하세요.
